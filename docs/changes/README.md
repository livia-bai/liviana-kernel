# 修改与验错记录

每一次涉及内核的改动（改了 `src/`、`user/`、`build.zig` 或链接脚本；通常对应一个提交，也可以是一组紧密相关的提交）都在这里留一篇记录：改了什么、为什么这样设计、怎么验证的、验证过程中发现了哪些问题、怎么修的。代码和功能文档描述的是“现在是什么样”，这里记录的是“怎么变成这样的”，包括走过的弯路。

写记录的规则见 [AGENTS.md](../../AGENTS.md#修改与验错记录)，模板在本文末尾。

## 模板

```markdown
# NNNN 标题

- 日期：YYYY-MM-DD
- 提交：`<短哈希>` <提交标题>（写记录时还没有哈希的，写“本记录对应的提交”，下一次改动时补上）
- 涉及文件：...

## 目标

要解决什么问题、实现什么功能。用户的原始要求是什么。

## 改动

按文件或按模块列出改了什么。新增的接口、数据结构、约定。

## 设计决策

为什么这样做；考虑过哪些别的做法，为什么没选。新引入的不变量。

## 验证

### 环境

Zig、QEMU、OpenSBI 的版本；有没有装额外的工具。

### 步骤和结果

实际运行的命令（可以直接复制再跑一遍），每种优化模式的结果，关键的输出。
临时测试代码（测完已删除）也贴在这里。

## 发现的问题

验证过程中发现的每一个问题，包括自己写错的地方：

### 问题 N：一句话描述

- 现象：看到了什么（原样贴出报错或输出）
- 原因：根本原因，不是表面原因
- 修复：怎么改的
- 确认：怎么确认修好了

没有发现问题也要写“没有发现问题”，并说明测了哪些情况。

## 遗留问题

已知但没有处理的问题、限制、以后可以做的事。
```
