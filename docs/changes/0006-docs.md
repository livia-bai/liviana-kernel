## 设计决策

- **按功能组织，再给一张文件对照表**：一个功能往往跨几个文件（比如进出 U 模式涉及 `trap.zig`、`proc.zig`、`vm.zig`），按文件写会把一件事拆散。每篇文档开头写明涉及的文件，`docs/README.md` 里有反向的对照表，满足“逐功能或者逐代码文件”两种查法。
- **文档里的数字和输出都实测**：地址、页数、体积、命令输出都是这次实际跑出来的，并注明了测量条件（通常是 Debug 模式、128 MiB）。没能验证的地方写明“推测”。
- **记录和代码在同一个提交里**，编号顺序排列；提交哈希在下一次改动时补上（自己的哈希在提交前无法知道）。
- **记录不回头改写**：后来发现记录有错，写在新记录里，旧记录加注指向新记录。0001–0005 是这次一起写的，所以直接写成了核实后的版本。

## 验证

### 环境

Zig 0.17.0、QEMU 8.2.2、OpenSBI v1.3（同前）；为了核实文档内容，另外装了 `gdb-multiarch`（GNU gdb 15.1）、`device-tree-compiler`（DTC 1.7.0），用到了系统自带的 LLVM 18 工具（`llvm-readelf`、`llvm-objdump`、`llvm-nm`）。

### 为写文档做的核实

文档里每一个“实测”的说法都对应下面的某一项。GDB 的会话都是 QEMU 加 `-s -S`、`gdb-multiarch -batch` 加一串 `-ex` 完成的（具体写法见 [testing.md](../testing.md#gdb)）。

| 核实的内容 | 方法 | 结果 |
| --- | --- | --- |
| GDB 能按 Zig 的符号名下断点 | `break vm.init`、`continue`、`bt 3` | 停在 `vm.init`，调用者是 `main.kmain` |
| 内核实际收到的设备树 | `break main.kmain` 后 `dump binary memory` 导出 `0x87e00000..0x87e01516`，`dtc` 反编译 | 保留区来自 `/reserved-memory/mmode_resv1@80000000` 和 `mmode_resv0@80040000`（都带 `no-map`），内存保留块为空 |
| GDB 显示内存的字节序 | `x/2wx 0x87e00000` | `0xedfe0dd0 0x16150000`：按小端显示，要倒过来读 |
| 一个程序运行时占多少页 | `break proc.switchToUser`，`print 'page.free_pages'` | 32052 → 32020，`hello`（Debug）占 32 页，和推算一致 |
| 内核页表和用户页表的实际内容 | `monitor info mem`，分别在 `plic.init` 和 `syscall.dispatch` 处 | 输出贴在 [paging.md](../paging.md#调试技巧) 和 [process.md](../process.md#用户地址空间)；保护页确实不在映射里 |
| U 模式能否读 `time` | 临时程序 `t_time`（执行 `rdtime`）；GDB `info registers scounteren` | 能读，没有陷阱；`scounteren = 0x7`，是 OpenSBI 设的 |
| `print` 每一段是一次系统调用 | `-d int -D` 日志里数 `user_ecall` | `hello` 12 次，`t_time` 4 次，和推算一致 |
| `ebreak` 的长度 | `llvm-objdump -d` | 两处都是 2 字节的 `c.ebreak`（`02 90`） |
| `zig build run -- ...` 透传参数 | `zig build run -- -d int -D <文件>` | 日志文件生成了（35 KB） |
| 缺入口时 `zig build` 的退出码 | 临时把 `user/start.zig` 的 `_start` 改名，`zig build -Doptimize=small` | 打印 `error: warning(link): ... cannot find entry symbol _start`、标 `failure`，但退出码 0，内核照样生成 |
| 正常构建没有输出 | 四种模式 `zig build` 的输出行数 | 都是 0 |
| 串口接收中断是电平触发 | 临时让 `uart.onInterrupt` 每次只读一个字符，`-d int` 数外部中断 | 30 个字符全部收到，30 次中断；原来的写法 2 次 |
| PCIe 窗口的地址 | `dtc` 看 QEMU 设备树 `pci@30000000` 的 `ranges` | 32 位 MMIO 窗口是 `0x4000_0000`，大小 1 GiB |
| 各段地址、体积 | `llvm-readelf -S/-l`、`llvm-nm` | 写进了 build.md、boot.md、paging.md |

临时的 `t_time`：

```zig
const sys = @import("sys");
pub fn main() u8 {
    const t = asm volatile ("rdtime %[r]"
        : [r] "=r" (-> usize),

    sys.print("rdtime from U-mode = {d}\n", .{t});
    return 0;
}
```

输出 `rdtime from U-mode = 19373354`，`exited with code 0`。测完已删除，`build.zig` 已还原。

## 发现的问题

写文档要求每个说法都核实，过程中发现了不少错误，包括旧文档、旧注释里的，也包括自己刚写的草稿里的。

### 问题 1：寄存器保存指令的条数写错

- 现象：`trap.zig` 的注释说 `regsAsm` 生成“31 条指令”，原 README 说保存/恢复寄存器“62 条指令”。
- 原因：x0 不用存、sp 单独处理，实际是 x1、x3..x31 共 30 个寄存器，存 30 条、取 30 条。
- 修复：注释改为 30 条，文档写 60 条。
- 确认：对照 `regsAsm` 的循环（`for (1..32)` 跳过 `i == 2`）。

### 问题 2：草稿里没核实就写下的说法

逐条核实后改正的：

| 草稿里的说法 | 实际情况 | 怎么发现的 |
| --- | --- | --- |
| U 模式不能读 `time`，因为内核没开 `scounteren` | 能读，OpenSBI 把 `scounteren` 设成了 7 | 临时程序 `t_time` + GDB 读 `scounteren` |
| 缺少 `_start` 时 LLD 的警告会让构建失败 | 退出码是 0，内核照样生成 | 临时改名 `_start` 复现 |
| 串口只读一个字符的话，剩下的要等下一次“有新数据”的中断 | 串口接收中断是电平信号，FIFO 里还有数据时 PLIC 会再次投递 | 临时把 `uart.onInterrupt` 改成每次只读一个字符，一次性发出 30 个字符：一个不丢，外部中断 30 次（原来的循环读法是 2 次）。第一次改的时候把循环里的 `continue` 留在了 `if` 里，编译失败、跑的是旧内核，实验无效，重做了一次。测完已还原 |
| “中断处理程序不打印” | 断点、进程退出这些打印发生在陷阱处理程序里，只是都是同步发生的 | 对照 `trap.zig` |
| `dtb.Info` 里的切片指向设备树 | `Info` 里只有数值 | 对照 `dtb.zig` |
| `PROP` 出现在“根节点之外”是 `BadToken` | 是出现在任何节点之外（`depth == 0`） | 对照 `dtb.zig` |
| OpenSBI 的保留区来自 `/reserved-memory`（当时没验证） | 确实如此，内存保留块是空的 | GDB 导出设备树 |
| 原来的 `crash` 得到 `load_access_fault` 是因为 PMP | OpenSBI 的 Region03 对 S/U 模式开放全部地址；是物理地址 0 处没有设备 | 对照启动横幅 |
| `0x8000_0000..0x8020_0000` 都被 PMP 保护 | 只有 `0x8000_0000..0x8006_0000` | 对照启动横幅 |
| Debug 内核 `.text` 约 311 KiB | 0x4befc 字节 = 304 KiB（311 是十进制 KB） | 重新计算 |
| 0005 的问题 1 里写“Debug 模式下 panic 被安全检查引用到，所以入口导出了” | safe 模式也有安全检查却失败了，这个解释不成立；机制没有深究，改为标明“推测” | 对照 safe 模式的结果 |
| 0005 的问题 2 写“0006 写文档时做了实验” | 那个实验是在提交 0005 之前做的 | 对照开发过程 |
| AGENTS.md 里查标准库的路径 `$(dirname $(which zig))/lib/std` | `zig` 是符号链接时会指到 `/usr/local/bin/lib/std`，不存在 | 实际执行；改用 `zig env` 的 `std_dir` |

### 问题 3：错误的锚点

- 现象：链接检查报 `docs/README.md: missing anchor devices.md#plicplic-zig`。
- 原因：标题 `PLIC（plic.zig）` 生成的锚点是 `plicpliczig`（`.` 被去掉，不是变成 `-`）。
- 修复：改成 `#plicpliczig`。
- 确认：链接检查全部通过。

### 问题 4：testing.md 里的命令输出不了内容

- 现象：“一键四种模式”的命令最后一步 `grep -E ...` 只输出 `grep: (standard input): binary file matches`。
- 原因：QEMU 的输出里有非文本字节，`grep` 把输入当成二进制文件，只报告“匹配”而不打印行。
- 修复：改成 `grep -a -E ...`。
- 确认：把文档里的命令原样复制执行，四种模式的关键行都正常打印。

### 问题 5：GDB 打印 Zig 的全局变量

- 现象：`print page.free_pages` 没有输出值。
- 原因：GDB 把 `page.free_pages` 解析成“变量 `page` 的成员 `free_pages`”。
- 修复：写成 `print 'page.free_pages'`（加单引号），写进了 [testing.md](../testing.md#gdb)。
- 确认：打印出 `$1 = 32020`。
